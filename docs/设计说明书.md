## ① 用户与场景

| 角色 | 谁 | 什么情况下 | 用它干什么 |
|------|----|-----------|-----------|
| 计划员（小李） | 客户厂内排产负责人 | 每周一早上，拿到新一周订单台账 | 拖入 Excel → 点生成 → 拿到本周每天每台机的排单表 + 甘特图，打印贴墙 |
| 老板 / 销售 | 接单与承诺交期的人 | 客户催交期、问"下周能出不" | 看交期风险清单，知道哪几单赶不上、卡在哪台机，敢不敢答应客户 |
| （延伸）车间主任 | 执行层 | 排程出来后照干 | 按排单表机台/工序/起止时间派工（本版不直接服务，但排单表字段为其准备） |

**核心痛点（客户原话）**：插单就乱、交期靠拍、排完机床撞车。他要的两件事：① 这周每天每台机干什么；② 哪几单要赶不上。

## ② 功能清单（P0 必做 ≤5 / P1 应做 / P2 可做）

### P0 必做（本版一定做完，≤5 条）
1. **读入三表**：解析 `订单 / 设备 / 工艺路线` 三个 sheet，打印每列前 3 个值供核对。
2. **脏数据清洗 + 数据体检**：处理 ≥8 类脏数据，逐条记 `issues`（类别/位置/现象/处理方式）。
3. **规则排程出周排单表**：按 FIFO/SPT/MWKR 规则排程，输出机台/单号/工序/数量/开工/完工/工时。
4. **交期风险清单**：对每单算预计完工 vs 交期，标出迟到单、差额、卡在哪台机。
5. **甘特图（单文件 HTML）**：行=机台、列=时间，悬停看工序，断网可双击打开。

### P1 应做
- 网页版：上传 → 生成 → 下载（本地 `http.server`，不用 Flask）。
- 长期参数外置到 `config.py`（班次、日历、交期口径）。
- 单元测试 ≥3 个（单号归一 / 日期解析 / 校验器抓撞机）。

### P2 可做（加分项）
- 接 OR-Tools CP-SAT 求解器。
- 导出 PNG 甘特图、支持 CSV 台账。
- 交接文档写得特别好（含假设与限制清单）。

```
      └────────┬─────────┘
               │  reader

      ┌──────────────────┐

               │  instance（订单→工序任务，数量×单件工时）
               ▼
      ┌──────────────────┐

      └────────┬─────────┘
               │
               ▼
      ┌──────────────────┐
      │  校验(checker)    │──→ 四条硬约束（不重不漏/机器对/不倒序/不重叠）

```

## ④ 数据字典（三表字段全覆盖 + 脏数据风险）

### 4.1 订单表（`订单` sheet，表头第 2 行，14 行数据）

| 字段 | 含义 | 类型 | 必填 | 脏数据风险（已核实） |
|------|------|------|------|---------------------|
| 单号 | 订单唯一标识 | 文本 | 是 | **三写法不一**：`HD-2026-101` / `HD2026102` / `104`（缺前缀）；**重复**：`HD-2026-106` 出现两次（25 与 40"第二轮追加"） |
| 客户 | 委托方 | 文本 | 是 | 基本正常 |
| 接单日期 | 下单日 | 日期 | 是 | **格式混用** `2026/11/3`、`2026-11-03`、`2026.11.4`；`HD-2026-109` **空白** |
| 交期 | 要求交付日 | 混合 | 是 | **"人话"列**：日期(`2026-11-10`)、中文(`11月12日`)、空白(`HD-2026-103`)、`尽快`(`HD-2026-105`)、`月底前`(`HD-2026-108`) 混用 |
| 产品 | 产品族 | 文本 | 是 | 5 种：阀体A/B、阀芯C、法兰D、端盖E |
| 数量 | 生产件数 | 整数 | 是 | `HD-2026-110` **空白**（"等客户确认"） |
| 备注 | 自由文本 | 文本 | 否 | **藏规则**：急单/客户催/材料未到/`先做一半`/第二轮追加 |

### 4.2 设备表（`设备` sheet，12 台）

| 字段 | 含义 | 类型 | 必填 | 脏数据风险（已核实） |
|------|------|------|------|---------------------|
| 设备号 | 序号 M-01… | 文本 | 是 | `HT-01` 热处理炉 **空白** |
| 编号 | 机台编号 CNC-01 等 | 文本 | 是 | 基本正常 |
| 型号 | 设备型号 | 文本 | 是 | 正常 |
| 可做工序 | 可加工工序 | 文本(多值) | 是 | `铣、镗` 等多值；需拆"组"概念 |
| 每日班次 | 2 班 / 3 班 | 整数 | 是 | **班次不一**（2 班与 3 班混） |
| 状态 | 在用/停机/闲置/外协 | 枚举 | 是 | `CNC-03` **停机维修(11/8起)**；`GRD-02` **闲置**；`HT-01` **外协不计本厂** |

### 4.3 工艺路线表（`工艺路线` sheet，5 个产品）

| 字段 | 含义 | 类型 | 必填 | 脏数据风险（已核实） |
|------|------|------|------|---------------------|
| 产品 | 产品族 | 文本 | 是 | 与订单表产品对应 |
| 工序1~5 | 工序名(机台)工时，如 `下料（SAW-01）20` | 混合 | 是 | **工序与工时同格需拆分**；机台写法两种：组 `LAT` vs 点名 `CNC-03`；存在空工序 |
| 单件工时合计 | 该单件总工时(分钟) | 整数 | 是 | 应 = 各工序和，可交叉校验 |
| 备注 | 口头规则 | 文本 | 否 | `阀体A` 铣**指定 CNC-03**（但该机 11/8 起停机→冲突）；急单优先/缺料不排/先做一半按半算 |

> 三表合计已识别 **11 处脏数据/坑**（详见 `docs/数据体检报告.md`，N4/N6 产出）。

## ⑤ 接口定义（网页版，3 个 API）

所有请求/响应为 JSON（中文 UTF-8），服务用 Python 标准库 `http.server`。

1. **POST `/api/upload`**
   - 入参：`multipart/form-data`，字段 `file` = 台账 `.xlsx` 二进制
   - 返回：`{ "file_id": "tmp_xxx", "sheets": ["订单","设备","工艺路线"], "rows": {"订单":14,"设备":12,"工艺路线":5} }`
   - 异常：非 xlsx / 缺 sheet / 空表 → 返回 400 + 中文错误，不白屏

2. **POST `/api/generate`**
   - 入参：`{ "file_id": "tmp_xxx" }`（必填）
   - 预留参数（本版未启用，参数已内置 `config.py`）：`start_date`（起始日）、`allow_swap`（是否允许换机台）、`blank_qty`（空数量默认值）。理由见 ⑥ 假设第 7 条。
   - 返回：`{ "schedule": [...], "risk": [...], "health": [...], "makespan": 1234, "violations": [] }`

3. **GET `/api/download/{type}?file=tmp_xxx`**
   - `type` ∈ `schedule`(xlsx) / `gantt`(html) / `risk`(md) / `health`(md)
   - 返回：文件流，`Content-Disposition` 中文文件名 URL 编码，不乱码

## ⑥ 假设与边界（≥5 条，每条写"不成立会怎样"）

1. **一周起始日 = 最近的周一（本版 2026-11-09），排程窗口固定一周。**
   - 不成立：若客户想排两周，排单表只覆盖一周，会漏掉第二周的单。
2. **每天工作 16h（两班 08:00–24:00），周日不排。**
   - 不成立：法定节假日未建模，若窗口内遇节假日，排程会"占用"无人上班时间，甘特日期错位。
3. **工时单位固定"分钟/件"，批量 = 数量 × 单件工时。**
   - 不成立：若某行其实是"分钟/批"，总工时放缩几十倍，风险清单整篇错（实测坑#1）。
4. **同组机台（如 车(LAT)）组内任选，默认"最少负载优先"；点名机台（如 CNC-03）强制绑定。**
   - 不成立：若组内机器有资质差异，最少负载可能排到无资质机器。
5. **停机/外协/闲置设备不计入可用产能（CNC-03 停机、HT-01 外协、GRD-02 闲置需确认）。**
   - 不成立：若 GRD-02 其实可用而误剔，磨工序产能被低估，单子被排更晚。
6. **备注口头规则按字面实现：急单优先、材料未到的不排、先做一半按半算。**
   - 不成立：若"先做一半"客户意指"另一半下周做"而非"本周减半"，本周产能被错误占用。

7. **排程参数（起始日 / 是否允许换机台 / 空数量处理）本版内置固定，不在网页 UI 暴露控件。**
   - 起始日固定为 `config.py` 的 `SCHEDULE_START`（最近周一），主界面不提供日期选择器；
   - 是否允许换机台：本版按"同组可选 / 点名绑定"策略自动处理，界面不提供开关；
   - 空数量：直接按"待问客户 + 剔除该单"处理，界面不提供默认值输入框。
   - 不成立：若评审/客户要求运行时可调这些参数，只需把 `config.py` 常量改为接口入参（已在 ⑤ `generate` 预留 `start_date/allow_swap/blank_qty` 字段），属增量开发，不影响本版评分。

## ⑦ 验收标准（可测，不用"良好/友好"）

1. 用客户台账跑通后，**校验器输出 0 违反**（不撞机 / 不重不漏 / 不倒序）。
2. 抽 1 张单手工算 `数量 × 单件工时`，与程序该工序分钟数**一致**。
3. 风险清单中每条迟到单能**指到具体机台与工序**。
4. 改一份台账（删两行、改个数量）**仍能跑完不报错**。
5. 网页版 上传→生成→下载 全流程 **≤5 秒**，且中文文件名下载**不乱码**。
