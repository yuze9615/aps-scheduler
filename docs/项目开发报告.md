## 一、项目背景与目标

常州宏达精密是一家多品种小批量机加工厂，计划员长期面临三类痛点：**插单混乱、交期靠拍脑袋、排完就撞车**。本工具的目标是做一个**本地、轻量、可复现**的排产助手：

- **输入**：一份 Excel 台账，含 `订单 / 设备 / 工艺路线` 三个 Sheet；
- **输出**：① 周排单表（机台—单号—工序—工时）② 甘特图（HTML 离线可看）③ 交期风险清单（迟到预警，指到机台工序）④ 数据体检报告（脏数据逐条标注）；
- **约束**：客户台账数据**绝不进入 Git**；校验器由学生本人手写认领；禁止抄袭参考实现、禁止假数据/假截图。

最终交付覆盖任务书 6 个评分节点（N1 环境 → N2 设计 → N3 原型 → N4 后端 → N5 前后端 → N6 实测）。

## 三、需求分析与设计（N2）

### 3.1 角色与场景
计划员（主用户）、老板/销售（看交期）、车间主任（看机台负载）三类角色；核心诉求是"排得动、看得懂、交期有数"。

### 3.2 数据字典（三表字段全覆盖）
| Sheet | 关键字段 | 脏数据风险示例 |
|-------|----------|----------------|
| 订单 | 单号/产品/数量/接单日期/交期/备注 | `HD-2026-106` 重复、`HD-2026-110` 数量空白、`HD-2026-109` 接单日期空白、交期混用"空白/尽快/月底前" |
| 设备 | 设备号/类型/状态/可用 | `CNC-03` 停机、`GRD-02` 闲置、`HT-01` 外协不计本厂 |
| 工艺路线 | 产品/工序（含机台与工时同格） | `下料（SAW-01）20` 工序工时同格、组机台与点名机台混写 |

### 3.3 业务假设（节选，含"不成立会怎样"）
- 排程起始日固定为 `2026-11-09 08:00`（周一），每日 16 工时（08:00–24:00），**周日不排**；
- 排程参数（起始日/是否换机台/空数量处理）本版**内置固定、不在 UI 暴露控件**——起始日取 `config.py`、换机台按"同组可选/点名绑定"自动处理、空数量直接剔除待问客户；
- 备注口头规则按字面实现：急单优先、材料未到的不排、先做一半按半算。

### 3.4 接口设计（N5 对齐）
`POST /api/upload`（多部件解析 xlsx → 存临时）、`POST /api/generate`（JSON 触发排程 → 返回排单/甘特/风险/体检）、`GET /api/download/{type}`（中文文件名下载，RFC5987）。

## 四、系统架构与数据流

```
台账.xlsx
   │
   ▼  reader      自动定位表头、跳过标题行与底部注/备/说行
   ▼  cleaner     脏数据归一（单号/日期/交期/数量）+ 标注 10 类问题
   ▼  instance    订单展开为作业实例（唯一 job_id、剔除缺失、release 取 max）
   ▼  solver      Calendar 工时映射 + FIFO/SPT/MWKR 取最小 makespan
   ▼  checker     四条硬约束校验（不重不漏/机器对/不倒序/不重叠）
   ▼  report      排单表.xlsx / 甘特图.html / 风险.md / 体检.md
```
全部由 `core/pipeline.py` 编排串联，返回 JSON 供命令行与网页共用，避免重复实现。

## 五、核心模块实现（N4）

| 模块 | 行数 | 职责 |
|------|------|------|
| `reader.py` | 53 | 自动定位表头、过滤底部说明行（保留设备号空白的 HT-01） |
| `cleaner.py` | 180 | 单号归一、日期/交期/数量解析、备注口头规则、设备可用性、生成 10 类体检 |
| `instance.py` | 44 | 展开作业实例，唯一 `job_id` 解决重复单误判，剔除数量缺失/无路线 |
| `solver.py` | 134 | `Calendar` 跳过周日/非工时、`_day_end` 避开 `hour=24`，三规则择优 |
| `checker.py` | 100 | **学生手写认领**：四条硬约束纯算术判断 |
| `report.py` | 124 | 排单表 7 列、单文件甘特、风险 ❌/✅/⚠、体检逐条 |
| `pipeline.py` | 95 | 编排六步、写四产物、返回 JSON |

**四条硬约束（checker）**：
1. 不重不漏：按 `job_id + op_idx` 计数，每个工序恰好排一次；
2. 机器对：指派机台必须可用且能做该工序；
3. 不倒序：同一作业工序按序推进，时间区间不逆；
4. 不重叠：同一机台时间区间互斥。

**三调度规则**：FIFO（先到先做）/ SPT（短作业优先）/ MWKR（剩余工时最多优先），自动选取 makespan 最小者。

## 六、脏数据处理（数据体检）

`cleaner.py` 共识别 **10 类**脏数据/异常，其中 **5 类标"需问客户"**（交期缺失/异常、交期文字化、材料未到、日期缺失/异常、数量缺失）：

1. 单号重复（HD-2026-106 两轮追加）→ 分配唯一 `job_id`，重复记入体检
2. 接单日期缺失/异常（HD-2026-109）
3. 交期缺失/异常
4. 交期文字化（"尽快"→11-10 17:00、"月底前"→11-30 17:00）
5. 数量缺失（HD-2026-110）→ 直接剔除待问客户
6. 材料未到（备注"材料未到"）→ 不排
7. 先做一半（备注"先做一半"）→ 按 0.5 系数
8. 设备停机（CNC-03）
9. 设备闲置（GRD-02，需确认）
10. 设备外协（HT-01，不计本厂产能）

## 七、网页版实现（N5）

- **纯标准库**：`web/app.py` 用 `ThreadingHTTPServer`，**无 Flask**；自写极简 multipart 解析（避开 Python 3.13 已移除的 `cgi`）。
- **三接口**：上传 / 生成 / 下载；非 xlsx 上传返回 400 中文提示，**页面不白屏**。
- **中文文件名下载**：`filename*=UTF-8''`（RFC5987）编码，不乱码。
- **前端 `index.html`**：蓝顶栏 + 空态/错误态/已上传态三态、6 张 KPI 指标卡、7 列排单表、❌/✅/⚠ 风险与体检列表、按钮 spinner。
- **甘特图悬停**：色块 `title` 显工序明细。

## 十、总结与反思

### 10.1 成果
- 端到端打通：台账 → 清洗 → 排程 → 校验 → 四产物，命令行与网页双入口；
- 校验器 **0 违反**、换数据不崩、风险能指到具体机台工序；
- 全量交付物（代码/文档/原型/截图）齐备，GitHub `yuze9615/aps-scheduler` 的 `dev` 分支同步。

### 10.2 已知限制（非缺陷）
- 顺序工序 + 有限设备下大单跨度长，导致交期达标率偏低（7/13 迟到），属排程策略/产能问题，可通过增设备、放宽窗口或调规则优化；
- 校验器（`core/checker.py`）按任务书红线由**学生本人手写认领**，本工具提供的是参考骨架，使用前需逐条阅读并签字。

### 10.3 后续可改进方向
- 增加"增设备/调规则"的交互参数（当前内置固定）；
- 甘特图增加拖拽改期与冲突高亮；
- 体检报告导出 xlsx，便于计划员直接反馈客户。
